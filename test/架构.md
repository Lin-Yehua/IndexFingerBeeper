# 项目架构（解耦实施版，函数级说明 + 当前实现映射）

## 文档目的
- 给出“解耦后目标模块”与“当前代码实现函数”的对应关系。
- 给出每一个已列函数的功能说明（目标函数 + 当前代码函数）。
- 明确哪些地方可以只搬移函数，哪些地方必须重构函数内部。

## 适用代码基线
- 主实现：`src/main.cpp` + `src/UsbAppMode.cpp` + `src/WirelessPortal.cpp`
- 时间：`2026-05-11`

---

## 0. 解耦实施原则（强约束）
### 原则A（默认）
- 不改函数体，仅做：函数搬移、命名空间/类封装、参数显式化、对外转发。

### 原则B（必须重构才改函数体）
- 仅当出现以下情况之一：
- 单函数承载多状态机，无法按逻辑块拆分。
- 关键状态隐藏在局部静态或闭包内，外部无法注入。
- 存在跨文件重复逻辑，导致行为不一致风险。

### 原则C（兼容）
- 迁移期保留旧函数名，内部转调新模块，再逐步删除旧实现。

## 2. 程序运行流程（解耦后，低层级跳转）
### 预启动流程
1. `main.setup()`
2. `BootOrchestrator.bootInitPeripherals()`
3. `UsbMscService.usbMscInit()` + USB状态判定
4. `BootOrchestrator.bootRunPreflightChecks()`
5. `StorageService`挂载文件系统
6. `UpdateService.scan + apply`
7. `RecoveryService.collectMissing + restore`
8. `PowerSleepService.tryFastResume()`
9. `BootOrchestrator.bootEnterInitialAppMode() -> AppController.init()`

### 主循环流程
1. `main.loop()`
2. `UsbMscService`处理插拔变化（必要时切USB）
3. `AppController.tick()`
4. `AppController`内部顺序：
5. `PowerSleepService`
6. `WirelessPortalService / StaFetchService`
7. `ScheduleService`
8. `InterruptController`
9. `DisplayService / AudioService`
10. 模式切换判定

### 模式关系
1. `APP_MODE_AP_STA`：短按播本地CSV，长按切`APP_MODE_STA_ONLINE`
2. `APP_MODE_STA_ONLINE`：联网播云队列，长按切`APP_MODE_STA_ONLY`
3. `APP_MODE_STA_ONLY`：被动监听，满足条件进深睡，长按切回`APP_MODE_AP_STA`

### 睡眠恢复
1. 计算下一唤醒时刻
2. 保存快照
3. 进入深睡
4. 定时/按键唤醒
5. 恢复快照
6. 回到`AppController`继续运行

## 3. 必须重构项（已标记）
### [R1] `processAppLoop` 巨函数拆分（必须重构）
- 触发点：`src/UsbAppMode.cpp:5151`
- 理由：中断仲裁+三模式状态机+按键+网络+显示全耦合，无法仅搬移函数完成解耦。
- 方法：
- 先提取`handleApStaMode/handleStaOnlineMode/handleStaOnlyMode`
- 再提取局部`InterruptController`结构体为类，字段和执行顺序保持不变
- 每次提取后保持日志与return路径不变

### [R2] `setting.ini` 多处重复解析/写回（必须重构）
- 触发点：
- `src/UsbAppMode.cpp:1923,4761,4809,4876`
- `src/WirelessPortal.cpp:1446,1714,1791,1056,1131`
- 理由：同项参数多处读写，易覆盖与漂移。
- 方法：先搬移到`ConfigService`，再统一解析/写回器，最后删重复实现。

### [R3] 全局状态强耦合（建议阶段2）
- 触发点：`include/AppGlobals.h`
- 理由：模块依赖不可见，不利于测试和并行迁移。
- 方法：引入`AppContext`，新模块先使用Context，旧代码用适配层桥接。

### [R4] 睡眠快照与队列恢复耦合（必须重构）
- 触发点：`src/UsbAppMode.cpp:3674,3823,3923,6063+`
- 理由：跨文件系统/队列/模式状态机，单文件维护成本高。
- 方法：提取`PowerSleepService`，保持快照格式不变，再把队列恢复交给`InterruptController`接口。

### [R5] 无线路由层与业务落盘耦合（建议重构）
- 触发点：`src/WirelessPortal.cpp` 路由与handler主体
- 理由：路由层承担参数校验、业务逻辑、落盘，函数链路过长。
- 方法：保留路由注册，拆handler到服务层，路由层只做解析+调用+回包。
